# Как добавлять материалы по предмету

Конвейер: файл → страницы → распознавание → структурирование → проверка сборщиком → утверждение в админ-панели → релиз.
Материалы добавляются постепенно; уже добавленные темы и записи **не удаляются и не перезаписываются** — только дополняются.

## Где что лежит

```
content/subjects.json                      реестр предметов (порядок, названия, значки, адреса)
content/subjects/<id>/src/00-structure.yaml  курс: файлы-источники, разделы, подразделы, словарь обозначений, замечания
content/subjects/<id>/src/NN-<подраздел>.yaml  темы одного подраздела: теория, формулы, примеры, вопросы
content/subjects/<id>/pages/               изображения страниц (в репозиторий не попадают) и список pages.txt
content/subjects/<id>/figures/             анимированные SVG-рисунки (делает tools/figures/make_figures.py)
content/subjects/<id>/student.yaml         исправленные тексты для студентов (если в материале есть ошибки)
content/subjects/<id>/review/decisions.json  перенесённые решения проверки (необязательно)
content/subjects/<id>/pack.json            собранная учебная база — не править вручную
docs/subjects/<id>.md                      журнал предмета: какие материалы получены и что добавлено
docs/subjects/<id>-report.md               автоматический отчёт об импорте
```

## Шаги

1. **Журнал.** Запишите в `docs/subjects/<id>.md` дату, файл, тип, число страниц и SHA-256 (повторный импорт того же файла не нужен).
2. **Страницы.** `python3 tools/import/pdf_to_pages.py файл.pdf content/subjects/<id>/pages <буква>` — изображения страниц для приложения и для распознавания. Буква — префикс ссылок на страницы этого файла (`a05`, `a12L`); у каждого файла предмета своя буква. В `sourceFiles` в `00-structure.yaml` укажите `pagePrefix` и, если файлов несколько, `pageLabel` — короткую метку в подписях (например, `лк` → «лк5»). Список страниц для публичного репозитория — `pages.txt` (имена файлов по одному на строку). Для учебника без изображений — `bookPages: [первая, последняя]` и `pdfOffset`.
3. **Распознавание.** Печатный PDF — `pdftotext`; скан или рукопись — Tesseract или `tools/import/transcribe.mjs` (нужен свой ключ API в переменной окружения на вашем компьютере; в приложение ключ не попадает). Транскрипт сверяется с изображением; неразборчивые места помечаются `[?]`.
4. **Структурирование.** Разделы и подразделы — в `00-structure.yaml`, темы — по файлу на подраздел. Все ID начинаются с префикса предмета (`ct-…` для Circuit Theory). У каждой записи — `src` (страница источника). Новые записи — **в конец** списков темы или с явным `id:`, чтобы не сдвинуть ID и историю ответов.
5. **Проверка сборщиком.** `npm run content:build` (строже — `npm run content:build:strict`). Сборка остановится при ошибке: несуществующая страница, неверный префикс ID, формула не рендерится, неизвестное обозначение, ответ не среди вариантов, числовой ответ не совпадает с выражением `check`, дубль вопроса.
6. **Утверждение.** В личной версии (артефакт с админ-панелью): «Админ-панель → Проверка» в нужном предмете. Сверьте запись с источником и утвердите. В тесты студентов попадают только утверждённые вопросы.
7. **Релиз.** Снимок решений → `npm run release:pack` → `npm run build:release` (см. [05 — сборка и публикация](05-release-guide.md)).

## Происхождение материала — честно

- Записи по материалам владельца ссылаются на страницу (`src`).
- Вопросы, которых нет в материалах, — **составленные**: в приложении они помечены «сгенерировано». Задание, взятое из материалов (например, из списка задач лекции), помечается `fromSource: true` — так оно учитывается в отчёте как «из источника». Нельзя ставить `fromSource` составленному заданию.
- Дополнения из интернета — только с разрешения владельца, с полем `web: [{ title, url }]` (https); `src` указывает место пробела в материалах. В приложении такие записи помечены «из интернета».
- Ошибки и противоречия материалов — в `errata` (`target`, `original`, `issue`, `suggestion`, `todo`); оригинал не исправляется. Исправленный текст для студентов — в `student.yaml`. Замечания видны только в админ-панели.
- Защищённые учебники не копируются целиком: в приложении — пересказ и свои задачи со ссылкой на место в книге.

## Формат записей (кратко)

```yaml
subsection: ct-dc            # подраздел из 00-structure.yaml
topics:
  - id: ct-ohm
    title: Закон Ома для участка цепи
    pages: [a03]
    theory:
      - { kind: definition, title: …, body: 'текст, формулы в $…$', src: a03 }
    formulas:
      - { title: Закон Ома, tex: 'I = \frac{U}{R}', sym: [I, U, R], src: a03 }   # sym — ключи из словаря symbols
    examples:
      - { title: …, given: …, steps: […], answer: …, src: a03 }
    questions:
      - type: single | multiple | numeric | matching | sequence | text
        cat: theory | formula | problem
        q: Текст вопроса
        opts: […]; ans: a            # single / multiple
        num: { value: 2, unit: 'А', check: '10/5' }   # numeric: check — независимый пересчёт
        pairs: [[…, …], …]           # matching
        seq: […]                     # sequence (в правильном порядке)
        ref: …                       # text: эталонный ответ
        hint: …                      # подсказка после первой ошибки
        explain: …                   # разбор
        sol: { given: […], find: …, formula: …, calc: …, answer: … }   # пошаговое решение
        src: a03
```

Предмет-учебник (`style: book` в реестре) дополнительно требует у темы `num`, `book.place`, `stage`, `sourcesChecked`, у формул — `meaning` и `use`, у задач — `sol`, а порядок тем задаёт `plan` (оглавление) в `00-structure.yaml`.

## Анимированные рисунки

Код рисунков предмета — `tools/figures/<id>/*.py` (декоратор `@fig` из `figlib.py`), запуск — `python3 tools/figures/make_figures.py <id>` → `content/subjects/<id>/figures/<рисунок>.svg`. ID рисунка начинается с префикса предмета, все `id` внутри SVG — с ID рисунка; цвета — только классы `s-*`, `f-*`, `t-*` (работает тёмная тема); скрипты и внешние ссылки запрещены. Подключение к теории — поле `fig:`.
