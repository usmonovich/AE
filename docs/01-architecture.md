# Архитектура AE

AE сделан из приложения UTC Preparation: тот же интерфейс, экраны, навигация, тесты, админ-панель и сборка. Отличие — предметы больше не зашиты в код, а задаются реестром `content/subjects.json`; учебное содержание каждого предмета отделено от интерфейса.

## Предметы

- `content/subjects.json` — список предметов: `id`, `prefix`, `emoji`, `icon`, `tone`, `title`, `short`, `tagline`, `style`, `vocab`, а также название приложения и префиксы хранилища.
- `src/data/subjects.ts` — читает реестр и строит описание каждого предмета: ключи хранилища (`ae.<id>.user.v1`, `ae.<id>.admin.v1`), документы базы артефакта (`ae/<id>/admin`, `data/users/<uid>/<id>`), виды резервных копий, словарь интерфейса («материалы» / «конспект» / «книга»).
- `src/data/packs.generated.ts` — статические импорты учебных баз всех предметов; создаётся `tools/build-content.ts` по реестру.
- `src/data/store.ts` — у каждого предмета своё хранилище прогресса и решений проверки; общие настройки (тема, шрифт) — в `ae.settings.v1`.
- Маршрутизация: `#/` — выбор предмета, `#/<prefix>/…` — экраны предмета. Адрес без известного префикса открывает выбор предмета.

## Стили предмета

| style | Источник | Страницы | Особенности |
|---|---|---|---|
| `notes` | файлы владельца: конспекты, лекции, слайды | изображения страниц (`a05`, `a12L`) | пометки «из интернета», замечания к источнику |
| `book` | учебник с оглавлением | печатные страницы без изображений (`b157`) | план курса по оглавлению, этапы тем, обязательные источники и пошаговые решения |

## Учебная база

`content/subjects/<id>/src/*.yaml` → `tools/build-content.ts --subject <id>` → `content/subjects/<id>/pack.json`. Сборщик проверяет ссылки на страницы, префиксы ID, рендер каждой формулы, ответы, независимый пересчёт числовых ответов и дубли. Все предметы — `npm run content:build` (`tools/content-all.mjs`).

## Проверка и релиз

Записи импортируются со статусом «на проверке». Утверждает только владелец в админ-панели личной версии (вход по PIN; в сборку встроен только хеш PIN из `.admin-pin`, файла нет в репозитории). `tools/release-pack.ts` оставляет в релизной базе только утверждённые записи; `npm run build:release` встраивает релизные базы и собирает приложение без админ-панели — так собираются сайт и приложения для магазинов.

## Сохранение данных

- Обычный браузер, Android, iOS — память устройства (localStorage), экспорт и импорт прогресса текстом или файлом.
- Личная версия в Claude (артефакт) — база артефакта: решения проверки — общий документ предмета (пишет только владелец), прогресс и настройки — личные документы пользователя.
- Supabase (необязательно) — вход, синхронизация, публикация учебной базы; таблицы общие, предмет определяется по префиксу ID и столбцу `subject` (миграция `0002_subjects.sql`).

## Тестовые предметы

`tests/fixtures/content` — два синтетических предмета («Предмет А» в стиле `notes`, «Предмет Б» в стиле `book`) со всеми типами записей и вопросов. На них работают e2e-тесты и часть unit-тестов, поэтому тесты не зависят от того, какие материалы уже загружены в настоящие предметы. В приложение тестовые предметы не попадают.
